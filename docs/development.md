# Git 开发约定

本项目使用 [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/)，标题格式为 `type(scope): description`。项目要求填写 scope，使用模块名或关注点，例如 `feat(forms): reject stale approvals`。正文在需要时解释原因、限制和验证方式。

| 类型 | 用途 |
| --- | --- |
| `feat` | 增加功能 |
| `fix` | 修复错误 |
| `docs` | 文档与开发约定 |
| `refactor` | 保持行为的代码重构 |
| `test` | 独立改进测试 |
| `chore` | 依赖、工具与项目维护 |

一个提交围绕一个可解释、可审查、可回退的意图。功能实现及其必要测试一起提交；相应需求、接口或安装说明同步更新。每完成一个小目标就检查差异、验证并提交，提交数量由实际工作决定。独立功能不要积攒成一个大提交，也不要按文件数量机械拆分。

提交前检查暂存内容和凭据隔离，执行与变更相关的验证。正常开发追加提交；改写已发布历史须有用户明确授权、恢复备份，并用 `--force-with-lease` 检查远端版本。
