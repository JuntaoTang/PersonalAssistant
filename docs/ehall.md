# ehall 后台能力

目标是用户在 iPhone 飞书发消息，Windows 后台助手访问南京大学办事大厅，返回查询结果、材料清单和具体填写预览。开发助手临时操作浏览器不计入该能力。

## 执行边界

- 查询与准备可直接由已绑定用户发起；查询结果保留来源、查询时间和覆盖范围，不能将服务目录查询说成个人成绩或审批状态查询。
- 首次或失效时用户在本机独立的登录窗口中登录；程序不保存密码，不从聊天收取密码。登录状态放在被忽略的 `data/ehall/`，日常任务使用无头浏览器，不常驻可见窗口。
- 第一种事务须由用户选择并根据真实页面验证。每种已支持事务有明确的入口、只读请求、字段与材料规则；未知事务不能交给模型自行点选或提交。
- 填写前经飞书展示字段、值、来源、缺项、材料和提交后果，用户确认对应版本后才输入。资料、字段、事务配置或页面变化导致旧确认失效；未知项留空。
- 自动填写不包含保存草稿、上传、提交、退课、撤回、撤销或删除。最终提交仍由用户亲自操作；涉及学籍、选课和撤销的决定不能由程序推断。
- 确认绑定用户、任务和完整预览；重复消息、重复确认和程序恢复不能重放外部写操作。浏览器自动触发的写请求也要阻断，不能只依赖“没有点击提交”。

## 验收

1. 飞书命令经过持久化队列后由后台执行；非绑定用户不能查询或确认。
2. 无有效登录时返回接管说明，普通查询不会启动可见窗口；登录状态只保存在本机。
3. 查询真实服务目录并返回名称、来源和时间；无权限或接口异常时明确失败，不伪造查询结果。
4. 至少一种用户选定事务完成真实材料准备与确认后填写；飞书回传填写结果和缺项。尚未选定或未实测时保持未验收。
5. 本地虚构页面验证未确认不输入、过期与重复确认无效、未知必填留空、页面变化停止、自动保存及提交请求被阻断、危险动作不能通过命令或模型输出执行。

## 当前接入

飞书支持 `ehall 登录`、`ehall 登录完成`、`ehall 状态`、`ehall 服务 关键词` 和 `ehall 结果 任务编号`，均在绑定用户检查后运行。查询进入现有持久化队列并建立 `ehall_query` 任务；结果可重看，重启不会重放中断查询。旧表单任务原地迁移为 `form`，查询任务不能使用公开表单的确认指令。普通表单入口拒绝接管 ehall 与学校身份认证链接，防止绕过适配边界。

目前已实现登录与服务目录客户端，使用固定的只读接口；已用本地 HTTP 服务检查状态复用、登录失效、响应不兼容及服务端登录核验，并以模拟飞书通道检查绑定、队列、去重、查询结果持久化与危险指令不执行。服务接口来自 2026-10-18 对公开门户脚本及匿名响应的检查，尚未用真实账号验证目录条目格式。首次事务和真实账号验收尚待完成；尚未编写或启用任意事务填写器。

公开入口为 [南京大学网上办事服务大厅](https://ehall.nju.edu.cn/)；登录状态复用依据 [Playwright 认证文档](https://playwright.dev/docs/auth)。
