# Lab 1 个人助手原型

电脑开机且未休眠时在后台运行；手机通过飞书机器人交互。当前先打通个人资料、表单预览／确认填写和英文邮件中文摘要，完整实验的其余范围见 [需求](requirements.md)，课程目标与开发原则见 [课程摘要](docs/course-context.md)，提交规范与历史整理说明见 [Git 开发约定](docs/development.md)。

## 日常启动

在资源管理器打开本目录 `D:\GSE\proj\PersonalAssistant`，双击：

| 文件 | 用途 |
| --- | --- |
| [启动助手.vbs](启动助手.vbs) | 在隐藏窗口中启动，提示结果；重复点击不会再启动一份 |
| [查看状态.vbs](查看状态.vbs) | 查看是否运行、飞书是否连接 |
| [停止助手.vbs](停止助手.vbs) | 停止后台助手 |

助手由本机 Node.js 运行，目前没有托盘图标或独立安装包。双击入口只显示简短结果提示，不需要保留窗口；任务管理器“详细信息”中可以看到运行 `src\cli.js run` 的 `node.exe`。启动后独立于终端、编辑器和本次聊天运行。

**电脑重启后需再次双击启动，尚未配置开机自启。** 休眠期间停止工作；唤醒后进程仍在时会继续检查邮件、恢复网络连接。入口依赖系统 Windows Script Host 和 PowerShell；若脚本被系统策略禁用，可使用文末的命令启动。

## 本地安装与配置

需要 Node.js 24+。在本目录运行：

```powershell
npm ci
npx playwright install chromium --only-shell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
npm run doctor
```

本目录 `.env` 覆盖课程目录 `D:\GSE\.env`；根目录仅包含一行 DeepSeek 密钥的格式也可读取。2026-10-13 已将用户根目录中带中文标签的凭据整理到项目 `.env`，原文件保留。后续请使用 `.env.example` 中的标准 `KEY=VALUE` 格式。主模型 `deepseek-flash`，备用 `deepseek-v4-flash`。依据[官方更新](https://api-docs.deepseek.com/news/news260910/)，备用目前是同一新版模型的兼容别名，因此无法提供独立服务的容灾。

真实配置、资料、数据库、截图、历史和日志均放在 Git 忽略的 `.env` 或 `data/`。个人资料入口是 `data/profile.md`；可直接编辑或在飞书发送 `资料 字段=值`。空值表示未知；当前带适用范围／有效期的事实保守留空，等待进一步处理。

## 查看和维护个人资料

实际使用的资料保存在本机 `data/profile.md`，默认完整路径为 `D:\GSE\proj\PersonalAssistant\data\profile.md`；配置 `ASSISTANT_DATA_DIR` 时随数据目录变化。[profile.example.md](profile.example.md) 是空白模板。真实资料被 Git 忽略，因此在 GitHub 上看不到。

- **电脑上**：用文本编辑器打开实际资料文件，按表格维护字段、值、适用范围和来源日期。下次读取即生效，无需重启助手；修改前应自行留一份副本。
- **iPhone 上**：助手运行并连接飞书时，私聊机器人发送 `资料` 查看全文；发送 `资料 姓名（中文）=你的姓名` 保存一项，发送 `资料 联系电话=` 清空一项。通过助手修改时，旧版本自动保存在本机 `data/profile-history/`。
- **在项目对话中**：可以让开发助手维护这份本地文件；这些修改也会被飞书机器人下一次读取。飞书机器人目前仍需使用上述字段指令，尚未支持从整段自然语言中自动提取并保存资料。

当前在读身份与未来升学安排分别记录，注明确认日期；未来学校不能当作当前学校。姓名拼写按用户原文保留，未提供的专业、学号、电话、入学日期等继续留空。当前实现对带适用范围／有效期的事实保守留空，不自动填进表单；资料变更后已有填表预览必须重新生成并确认。

## 飞书机器人

使用独立的**企业自建应用机器人**，需要能创建和发布应用的飞书组织。不是群聊里的 Webhook 自定义机器人。

1. 在[飞书开放平台](https://open.feishu.cn/app)创建自建应用，启用机器人能力；可用范围先设为自己。
2. 配置应用身份权限：读取用户发给机器人的单聊消息 `im:message.p2p_msg:readonly`、以应用身份发消息 `im:message:send_as_bot`、图片资源 `im:resource`。权限名称以控制台实际显示为准。
3. 将 App ID、App Secret 写入本目录 `.env` 的 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET`。不要发送到聊天中。
4. 运行 `npm run start`，用 `npm run status` 确认连接状态。事件配置选择“使用长连接接收事件”，添加 `im.message.receive_v1`。
5. 创建版本并发布，使权限和事件生效。若有管理员审核，按组织流程完成。
6. 本机运行 `npm run doctor -- --pairing` 获取绑定指令，在 iPhone 飞书里私聊机器人发送。首次绑定后仅接受该用户的私聊指令。

不需要公网 IP、端口映射或常开的桌面聊天窗口。[官方 SDK](https://github.com/larksuite/node-sdk/blob/main/README.zh.md)说明长连接机制；接口参考：[收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[发消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[传图片](https://open.feishu.cn/document/server-docs/im-v1/image/create)。

## 邮箱

本地 `.env` 的 `MAIL_USERNAME` 已记录用户提供的 smail 地址。按[南大官方说明](https://itsc.nju.edu.cn/_s302/1a/8f/c21586a334479/page.psp)开启 IMAP，使用 `imap.exmail.qq.com:993`、TLS、完整邮箱用户名；需要客户端专用密码时，按照[官方密码说明](https://itsc.nju.edu.cn/96/2e/c21475a497198/page.htm)生成，将其写入本地 `MAIL_PASSWORD`。

配置模板默认关闭读取。用户于 2026-10-13 确认“所有新增英文邮件”，本机已经开启：

```dotenv
MAIL_ENABLED=true
MAIL_SCOPE=all-new-english
MAIL_POLL_SECONDS=300
```

改配置后重启助手。首次成功连接只记下当时最新 UID，此后每 5 分钟检查新增邮件，关机后的积压会补查。英文识别目前是字符比例启发式，可能漏掉中英混合邮件；原始邮件超过 5 MB 会跳过，正文仅取前 40000 字符。附件、历史往来、论文主题分类、回复和发信尚未实现。

摘要包含目的、待办、原文截止日期／时区、要求及不确定项，附原邮件 Message-ID 和邮箱入口。摘要所需邮件正文，以及表单匹配所需字段与资料会发送给配置的 DeepSeek API；仅在对应任务启用后处理。

## 手机指令与填表

| 指令 | 行为 |
| --- | --- |
| `资料` | 查看当前个人资料 |
| `资料 常用邮箱=example@example.org` | 保存明确提供的事实，保留修改前版本 |
| `资料 联系电话=` | 清空该字段 |
| 一个表单 URL | 读取并展示拟填字段、留空项与确认码 |
| `确认填表 任务编号 确认码` | 对应资料与表单未变化时才填写 |
| `进度` | 查看最近任务 |
| `帮助` | 查看指令 |
| `ehall` | 查看 ehall 后台能力与限制 |

只支持公开网页上的普通输入框、文本区、下拉框和单选框。模型负责匹配，填入值必须来自资料；未知、歧义或不匹配的选项留空，包括必填项。预览确认前不输入个人数据；填写后核对字段并返回截图。**最终提交由用户亲自操作**。当前后台页面不能直接转移到 iPhone，接手方式仍待确认和实现；后台页面在退出时关闭，截图不等于提交成功。

用户示例问卷当前停止作答，尚未在该问卷上验证兼容性。登录、验证码、多步骤、文件上传、iframe 和复杂动态控件待实际需求驱动扩展。

## 从手机使用 ehall

由 Windows 后台程序执行，发起任务后可关闭本次开发对话。首次使用时，先启动助手，再在 iPhone 飞书私聊机器人：

1. 发送 `ehall 登录`。电脑上会打开独立的 Edge 登录窗口；在该窗口手动完成学校登录。程序不接收密码或代解验证码。
2. 发送 `ehall 登录完成`。后台向 ehall 核验登录，成功后保存本机状态并关闭窗口。以后的查询无需保持可见窗口；登录失效会提醒重新操作。
3. 发送 `ehall 服务 课表` 等关键词。后台查询当前账号可见的服务目录，返回名称、来源、时间和任务编号。
4. 发送 `ehall 课表` 查询本人的本科课表。按学校返回的当前学期展示已排课、待开课程和未排课，保留周次、星期、节次、地点、教师及说明；不按日期猜学期，不将节次换算成钟点。
5. 发送 `进度` 查看状态，或 `ehall 结果 任务编号` 重看本人的查询结果。任务和结果保存在本机 SQLite，助手重启后仍可读取。

`ehall 状态` 只报告是否保存过登录状态，实际有效性在请求时核验。浏览器登录状态保存在 Git 忽略的 `data/ehall/state.json`，不要分享或上传。普通浏览器中已经登录，不代表后台已经取得这个独立会话。

目录查询和个人课表查询分别使用上述命令。2026-10-18 已完成手机发起的真实目录查询，以及个人课表客户端的真实账号读取；新增 `ehall 课表` 命令仍待手机端反馈。**材料准备与具体事务填写尚未适配。** 未知事务、提交、退课和撤销不会执行。首个真实事务选定后按 [ehall 规约](docs/ehall.md)继续验收。

## 启停与验证

```powershell
npm run start
npm run status
npm run stop
npm test
npm run doctor -- --model
```

启动进程独立于终端，Windows 使用 `windowsHide`；启动后可关闭终端。当前没有配置开机自启。`data/status.json` 保存连接状态与心跳，`data/background.log` 保存简短运行信息。不要同时为同一机器人运行多个事件接收程序。

测试使用虚构资料和本地 HTML 表单，检查确认门槛、未知必填项留空、不提交、变更导致确认失效、去重、持久化和模型故障切换。`doctor --model` 单独进行一次不含个人信息的真实 API 连通测试。

`node src/cli.js start --offline` 仅用于测试后台存活与停止，不连接飞书、不访问邮箱。实际账号联调仍需在手机收发消息和新邮件上验收。
